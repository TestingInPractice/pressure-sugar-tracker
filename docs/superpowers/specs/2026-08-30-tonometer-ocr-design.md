# Дизайн-спецификация: распознавание давления по фото тонометра

Дата: 2026-08-30
Статус: утверждена (brainstorm, 2026-08-30)
Проект: pressure-sugar-tracker (офлайн-PWA, React 19 + TS 5.9 + Dexie 4 + Vitest 3)

## 1. Проблема и цель

Пользователь измеряет давление цифровым тонометром и ведёт журнал в PWA-приложении
«Трекер давления и сахара». Ручной ввод чисел с экрана тонометра — рутина и источник
опечаток. Цель фичи: пользователь выбирает фото экрана цифрового тонометра из галереи,
приложение распознаёт числа (систола / диастола / пульс) локально в браузере и
подставляет результат в форму записи. Пользователь правит значения при необходимости
и сохраняет запись обычным способом.

Фича работает полностью офлайн: распознавание выполняется в браузере (Tesseract.js,
wasm), фото никуда не отправляется.

## 2. Решения, принятые в brainstorm

| Вопрос | Решение |
|---|---|
| Тип тонометра | Только цифровой с ЖК-экраном |
| Источник фото | Только выбор файла из галереи (input file) |
| Где распознавать | Локально в браузере, Tesseract.js (вариант A) |
| Куда результат | Подстановка в форму записи, сохраняет человек вручную |
| Привязка к полям | Только поле с именем «ВД / НД / П» (текстовый формат `120/70/100`) |
| Объём первого релиза | Минимум: кнопка → распознавание → подстановка; без превью, кропа, облака |

## 3. Архитектура

```
EntryForm (ReportScreen)
   │  «Фото» → input[type=file accept="image/*"]
   ▼
src/logic/ocr.ts                    ← динамический import('tesseract.js')
   │  worker (eng, whitelist цифр/разделителей), recognize(File) → текст
   ▼
src/logic/ocr-parse.ts              ← чистая функция, без I/O
   │  чистка символов, поиск чисел, валидация диапазонов
   ▼
"120/80/65" → значение поля «ВД / НД / П» в state формы
   │  (пользователь правит → обычный onSave)
   ▼
putEntry(в IndexedDB)
```

### 3.1 Модули

| Модуль | Назначение | Зависимости | Тестируемость |
|---|---|---|---|
| `src/logic/ocr.ts` | Ленивая загрузка Tesseract.js, инициализация worker'а (eng), распознавание `File` → текст. Инкапсулирует ресурсы worker'а (создание/освобождение), конфигурацию (whitelist, PSM) | `tesseract.js` (dynamic import) | Обёртка над движком; юнит-тест с фейковым worker — минимум |
| `src/logic/ocr-parse.ts` | Сырой текст OCR → `PressureReading` с валидацией диапазонов. Чистая функция | нет | Полное юнит-покрытие (основной объём тестов) |
| `src/components/EntryForm.tsx` (изм.) | Кнопка «Фото», статус распознавания, подстановка значений в поле «ВД / НД / П» | `ocr.ts`, `ocr-parse.ts` | Юнит-тесты с моком `ocr.ts` |

### 3.2 Данные

```ts
// Результат распознавания после парсинга
interface PressureReading {
  sys: number | null;   // систола, 60–250
  dia: number | null;   // диастола, 40–150
  pulse: number | null; // пульс, 30–220
}

// Формат подстановки в поле «ВД / НД / П»:
// все три:  "120/80/65"
// без пульса: "120/80"
// только систола: "120"
// ничего не распознано: поле не трогается
```

### 3.3 Парсер (ocr-parse.ts)

- Вход: сырая строка из Tesseract.js, напр. `"1Z0 8O 65"`, `"120/80/65 mmHg"`, `"120 80"`, мусор.
- Нормализация типичных OCR-ошибок в цифрах: `O→0`, `o→0`, `I→1`, `l→1`, `|→1`, `S→5`, `B→8`.
- Разделители: `/`, `-`, пробелы; выбросить всё нецифровое окружение (mmHg, символы, буквы).
- Правило извлечения: берутся до трёх чисел, каждое проходит проверку диапазона
  (sys 60–250, dia 40–150, pulse 30–220); вне диапазона значение = null.
- Порядок: первое валидное = sys, второе = dia, третье = pulse.
- Пустой/невалидный вход → `{ sys: null, dia: null, pulse: null }`.

## 4. UI-поток (EntryForm)

Кнопка «Фото» отображается только если в `fields` отчёта есть поле с именем «ВД / НД / П».

```
[Фото] → file input (accept="image/*")
   ├─ нет поля «ВД / НД / П» → кнопка скрыта
   ▼
Статус: «Распознаю…» (обработка фото, повторный выбор заблокирован)
   ├─ OCR успех → «Готово: 120/80/65» → значения влиты в поле «ВД / НД / П»
   ├─ распознан частично → «Готово: 120/80» → аналогично
   ├─ нет чисел → «Не удалось распознать. Попробуйте другое фото» → поле не трогаем
   └─ ошибка движка/worker'а → «Распознавание недоступно. Попробуйте ещё раз»
        → поле не трогаем
```

- Значения попадают в существующий state формы (`values`), пользователь может
  править их ДО сохранения. Экономия на повторном вводе, автосохранения нет.
- Повторный выбор фото перезапускает распознавание и перезаписывает значение поля.
- Все ошибки мягкие: статусная строка под кнопкой, форма не ломается,
  остальные поля и обычное сохранение работают как раньше.
- Распознавание не менять никаких других полей (дата/время, сахар, примечание).

## 5. Офлайн и размер

- `tesseract.js` подключается как обычная зависимость, но загружается только через
  `import('tesseract.js')` в момент первого использования (отдельный чанк, бандл
  приложения не раздувается).
- Файлы модели (`eng.traineddata`) и wasm-core кладём в `public/` проекта —
  Tesseract.js настраивается на локальную загрузку (langPath/corePath), без CDN.
- После первого успешного использования ассеты кэшируются Service Worker'ом
  (vite-plugin-pwa уже настроен: registerType autoUpdate) — повторное использование
  и последующие запуски работают офлайн.
- Деплой на gh-pages: статические ассеты в `public/` попадают в сборку автоматически.

## 6. Обработка ошибок

| Сценарий | Поведение |
|---|---|
| Фото выбрано, OCR не нашёл чисел | Статус «Не удалось распознать. Попробуйте другое фото», поле не меняется |
| Worker не смог инициализироваться (первый запуск офлайн и ассеты не скачаны) | Статус «Распознавание недоступно. Попробуйте ещё раз», поле не меняется |
| Повторный выбор файла | Распознавание перезапускается, статус «Распознаю…» |
| Не-изображение (пользователь выбрал не картинку) | Отклоняется фильтром accept + статус «Не удалось распознать…» |
| Любая ошибка во время распознавания | Статус «Распознавание недоступно. Попробуйте ещё раз» |

Ни один сценарий не приводит к потере данных формы: состояние формы (values)
изменяется только при успешном распознавании чисел.

## 7. Тестирование

Подход: детерминированные юнит-тесты. Реальный Tesseract.js в тестах не запускается
(недетерминирован, тяжёлый, требует wasm). Вместо этого:

| Модуль | Кейсы |
|---|---|
| `ocr-parse.test.ts` | Мусор → null; `"1Z0 8O 65"` → 120/80/65; разделители `/` `-` пробелы; частичное (2 числа → dia null → pulse null); любое число вне диапазона → null; `"120/80/65 mmHg"` → ок; пустой ввод → все null |
| `EntryForm.test.tsx` | Mock `ocr.ts`: успех → значение в поле; частичный успех; мусор → статус и поле без изменений; ошибка worker → статус недоступности; кнопка скрыта при отсутствии поля «ВД / НД / П»; повторное фото перезапускает распознавание; остальные поля не меняются |
| `ocr.test.ts` (минимум) | Фабрика: передаёт файл в worker, возвращает текст (фейковый worker) — страховая от регрессий интеграции |

## 8. Границы фичи (вне scope)

- Не делаем: облачное распознавание / API-ключи / серверы.
- Не делаем: превью фото, кроп, поворот, улучшение изображения перед OCR.
- Не делаем: хранение фото в IndexedDB.
- Не делаем: распознавание механических (стрелочных) тонометров.
- Не делаем: подстановку в произвольные поля — только «ВД / НД / П».
- Не делаем: автозаполнение других полей формы (дата/время и пр.).

## 9. Критерии приёмки

- [ ] В отчёте с полем «ВД / НД / П» в EntryForm есть кнопка «Фото»; без поля — нет.
- [ ] Выбор изображения запускает локальное распознавание; при успехе значения
      (sys/dia/pulse из диапазонов) подставляются в поле в формате `120/80/65`.
- [ ] Частичное распознавание подставляет имеющиеся значения; пустой результат
      оставляет поле без изменений и показывает статус.
- [ ] Ошибки не ломают форму; обычное сохранение записи работает как раньше.
- [ ] `npx vitest run` — все тесты зелёные (старые + новые); `tsc -b` без ошибок.
- [ ] Первый запуск распознавания скачивает ассеты один раз; повторный работает офлайн
      (проверяется вручную на деплое).
