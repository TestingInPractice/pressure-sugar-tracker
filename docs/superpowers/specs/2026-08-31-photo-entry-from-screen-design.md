# Дизайн — распознавание давления с главного экрана отчёта

Дата: 2026-08-31
Статус: утверждено пользователем (ответы на уточняющие вопросы + «делай»)

## 1. Цель

Перенести запуск распознавания давления по фото с кнопки внутри поля «ВД / НД / П» на главный экран отчёта (рядом с «Печать/PDF» и «+ Запись»). По нажатию «Фото» пользователь выбирает фото ЖК-тонометра, приложение локально распознаёт цифры, ставит текущую дату в поле «Дата и время» и открывает **полную форму записи**, предзаполненную распознанными значениями. Пользователь при необходимости правит цифры и сохраняет как обычно.

## 2. Решения (утверждены пользователем)

| Вопрос | Решение |
|--------|---------|
| Что открывается после выбора фото? | Полная форма `EntryForm`, предзаполненная |
| Куда ставится «текущая дата»? | В поле «Дата и время» (`datetime-local`, локальное `yyyy-MM-ddTHH:mm`) |
| Кнопка «Фото» внутри поля | Убрать (вместе с OCR-кодом/тестами/стилями в `EntryForm`) |
| Отчёт без поля «ВД / НД / П» | Кнопку «Фото» НЕ показывать |
| Ошибка/мусор распознавания | Форма открывается всегда: дата ставится всегда, поле «ВД / НД / П» заполняется если распознано, иначе пустое (можно вписать вручную); статус-сообщение показывается в форме |

## 3. Архитектура

- **Переносимый слой остаётся**: `recognizeTextFromImage` (src/logic/ocr.ts), `parsePressureText` + `formatPressureReading` (src/logic/ocr-parse.ts) — без изменений.
- **Логика запуска переносится** из `EntryForm` в `ReportScreen`:
  - В `ReportScreen` добавляется скрытый `<input type="file" accept="image/*">` внутри label-кнопки «Фото».
  - `handlePhoto(file)`:
    1. `recognizeTextFromImage(file)` (динамический импорт tesseract — уже внутри module).
    2. `parsePressureText(text)` → `formatPressureReading(reading)` (может быть `''`).
    3. Собирает `initial = { [dtFieldId]: nowLocal, [bpFieldId]: formatted? }`.
    4. `setEditingEntry(null); setShowForm(true)` — форма открывается всегда.
  - Текущая дата: `toLocalInputValue(new Date().toISOString())` из `src/logic/reminders.ts` — уже существующий хелпер, возвращает `yyyy-MM-ddTHH:mm` в локальных компонентах.
  - Статус-сообщение («Готово: …» / «Не удалось распознать…» / «Распознавание недоступно…») передаётся в `EntryForm` через новое необязательное prop `photoResult?` и показывается в форме.

## 4. Компоненты и интерфейсы

### ReportScreen.tsx (модификация)
- Новое состояние: `ocrStatus: 'idle'|'working'|'done'|'error'`, `photoMessage: string`.
- Кнопка «Фото» (`.no-print`), видна только если есть поле «ВД / НД / П» (`bpField`).
- Label-обёртка: `Фото` / `Распознаю…` + скрытый file input.
- `handlePhoto(file)`: guard `!file || !bpField || ocrStatus==='working'`.
- Передаёт в `EntryForm`: `initial` (собранный) + `photoResult={{ status, message }}`.

### EntryForm.tsx (модификация)
- Удалить: `ocrStatus`, `ocrMessage`, `handlePhoto`, блок `.photo-row`, импорты `recognizeTextFromImage`, `parsePressureText`, `formatPressureReading`, `OcrStatus` тип.
- Добавить необязательное prop `photoResult?: { status: 'idle'|'done'|'error'; message: string }`.
- Показывать `photoMessage` под формой (статус-строку) если `photoResult` не `idle`.
- **Важно**: сейчас поле «ВД / НД / П» без unit рендерится как `<textarea>` (ветка `else`), а не `<input type="text">`. Это существующее поведение — предзаполнение идёт через `initial[bpField.id]`, рендер не меняем (только убираем placeholder из input-ветки, т.к. она мёртвая).

### src/index.css (модификация)
- Удалить `.photo-row`, `.photo-btn`, `.photo-btn:hover`, `.photo-row em.ok` (переносим на главный экран). Кнопка на главном экране использует существующий стиль кнопок `.no-print`.
- Возможно добавить стиль для статус-строки в EntryForm (`em.ok`/`em.error` уже используются).

## 5. Поток данных

```
[Фото] (главный экран, только при наличии поля ВД/НД/П)
  → file input → файл
  → recognizeTextFromImage(file)         // ocrStatus='working', «Распознаю…»
  → parsePressureText → formatPressureReading → formatted ('' если пусто)
  → initial = { [dtFieldId]: nowLocal, [bpFieldId]: formatted }
  → setShowForm(true)                    // открыть EntryForm
  → photoResult = { status, message }    // «Готово: …» / «Не удалось…» / «Недоступно…»
  → пользователь правит/сохраняет
```

## 6. Ошибки и крайние случаи

- **Нет поля «ВД / НД / П»**: кнопка «Фото» не рендерится.
- **worker недоступен** (throw): форма открывается, поле пустое, дата стоит, сообщение «Распознавание недоступно. Попробуйте ещё раз».
- **мусорный текст** (формат распознан как ''): поле пустое, сообщение «Не удалось распознать. Попробуйте другое фото».
- **повторный выбор того же файла**: `e.target.value = ''` после обработки.
- **двойной клик во время распознавания**: guard `ocrStatus === 'working'`.
- **нет поля «Дата и время»**: `dtFieldId` может быть `undefined` — дату не ставим, остальное работает.

## 7. Тестирование

- `ReportScreen`:
  - Кнопка «Фото» есть, когда есть поле «ВД / НД / П»; нет — когда нет.
  - Успех: после выбора фото открывается форма, дата = сегодня (`yyyy-MM-ddTHH:mm`), поле ВД/НД/П = `120/80/65`.
  - Мусор: форма открывается, дата стоит, поле пустое, сообщение «Не удалось распознать».
  - Worker ошибка: форма открывается, сообщение «Распознавание недоступно».
  - Мок `../logic/ocr`.
- `EntryForm`:
  - photoResult=done показывает «Готово: …», error показывает сообщение, idle — ничего.
  - OCR-тесты формы удаляются (кнопка убрана).
- Полный прогон: `npx vitest run && npx tsc -b`.

## 8. Критерии приёмки

- [ ] Кнопка «Фото» на главном экране только при наличии поля «ВД / НД / П».
- [ ] По нажатию «Фото» → выбор фото → открывается полная EntryForm с текущей датой в «Дата и время» и распознанным значением в «ВД / НД / П».
- [ ] При ошибке/мусоре форма всё равно открывается (дата стоит, значение пусто), сообщение видно.
- [ ] Кнопка «Фото» внутри поля удалена (нет дублирующего ввода).
- [ ] Работает офлайн (ассеты tessdata на месте).
- [ ] Все тесты зелёные, tsc чист.
